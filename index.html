  • 숫자의 범위와 게임 규칙
  • 화면에 나오는 문구와 형식

코딩 프롬프트의 우선순위: 목적(P)이 먼저입니다

일반적인 프롬프트 작성법에서는 "너는 ○○ 전문가야"처럼 Persona를 맨 앞에 쓰라고 안내하는 경우가 많습니다. 하지만 AI가 무엇을 만들어야 하는지 모르면 어떤 역할을 맡든 엉뚱한 코드가 나옵니다. 반대로 목적과 조건만 분명하면 Persona가 없어도 원하는 프로그램은 만들어집니다.

"너는 20년 경력의 파이썬 전문가야"라고 써도 코드가 더 정확해지지는 않습니다. 오히려 아직 배우지 않은 고급 문법이 나올 수 있습니다.

구체적인 지시가 더 확실합니다

"친절하게"는 AI마다 해석이 다르지만, "모든 줄에 한글 주석"은 해석의 여지가 없습니다. 그래서 Persona에는 한글 주석, 짧은 실행 순서 요약처럼 구체적인 설명 방식을 함께 씁니다.

자세한 설명은 코드를 읽은 뒤에 묻습니다

어느 부분이 어려운지는 코드를 읽어 봐야 알 수 있습니다. 첫 프롬프트에서는 기본 설명만 요청하고, 이해가 안 되는 줄은 후속 질문으로 묻습니다.

건강 관리 리포트 생성기

문제를 먼저 읽고, 문제의 조건이 예제 프롬프트의 어느 요소로 옮겨졌는지 찾아보세요.

문제

우리는 학교나 직장에서 매년 건강검진을 받는다. 검진 결과지에는 나의 키와 몸무게를 바탕으로 계산된 '체질량지수(BMI)'와 그에 따른 '비만도 판정'이 적혀 있다. 다음 조건을 만족하는 '건강 관리 리포트 생성기'를 작성해야 한다.

  1. 사용자로부터 이름, 키(cm), 몸무게(kg)를 입력받는다.
  2. 함수를 사용하여 BMI를 계산하고, 지수에 따라 '저체중, 정상, 과체중, 비만' 중 하나로 판정한다.
  3. 계산된 모든 정보(이름, 키, 몸무게, BMI, 판정 결과)를 'health_report.csv' 파일에 차곡차곡 저장한다.
  4. BMI = 체중(kg) / (키(cm) / 100)²
판정 기준: BMI < 18.5는 저체중, 18.5 ≤ BMI < 23은 정상, 23 ≤ BMI < 25는 과체중, 그 이상은 비만

숨은 조건을 찾아 썼어요

문제에는 없지만 R에 추가한 조건이 있습니다. "기록이 지워지지 않고 계속 추가", "제목 줄은 처음 한 번만", "엑셀에서 한글이 깨지지 않게"를 빠뜨리면 AI가 덮어쓰기로 저장하거나 실행할 때마다 제목 줄을 반복하는 코드를 만들기 쉽습니다. 잘못된 값을 넣었을 때 다시 입력받는 동작도 프로그램의 기능이므로 R 5번에 적었습니다.

문제

입력하기 전에

왜 새 코드 셀일까?

따로 요청하지 않으면 AI는 기존 코드를 고친 버전을 줍니다. 새 셀에 독립적으로 작동하는 코드를 받으면 1단계 코드가 그대로 남아 비교하고 되돌리기 쉽습니다.
